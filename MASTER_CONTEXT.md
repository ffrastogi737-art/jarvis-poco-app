2. JARVIS कैसा होना चाहिए
JARVIS केवल सवालों के जवाब देने वाला AI नहीं होना चाहिए।
उसे तीन चीजों का combination होना चाहिए:
🧠 Brain
AI reasoning, planning, memory, research और decision-making।
👁️ Eyes & Ears
Camera, microphone, screenshots, documents, screen आदि से information लेना।
🖐️ Hands
Phone, laptop, browser, files, apps, email, calendar और दूसरे digital tools में actual actions करना।
मतलब:
देखे → समझे → plan करे → action ले → result check करे → काम पूरा करे → मुझे बताए।

4. हमने capability list को बहुत बड़ा किया

 * Cross-device: Phone, Laptop, Future PC, Cloud, Wearables, Smart devices.
5. सबसे महत्वपूर्ण requirement — JARVIS proactive & "Always Thinking" होना चाहिए
मैं नहीं चाहता कि हर बार मुझे JARVIS खोलकर पूछना पड़े: "काम हुआ?"
JARVIS को खुद पता होना चाहिए कि कोई काम पूरा हुआ है या नहीं।
A. Proactive Execution:
मैं बोलता हूँ: "JARVIS, client के लिए meeting fix कर दो।"
JARVIS background में: Calendar check → available slot → meeting schedule → confirmation.
फिर मुझे खुद बताता है (कॉल या वॉइस नोट के ज़रिए)।
B. Continuous Idle Processing:
जार्विस सिर्फ कमांड का इंतज़ार न करे। जब मेरा डिवाइस खाली (idle) हो, वह बैकग्राउंड में काम करे।
जैसे बिना मेरे पूछे बैकग्राउंड में Python scripts रन करके मार्केट ट्रेंड्स ट्रैक करना या नए डिस्ट्रीब्यूशन कॉन्टैक्ट्स की लिस्ट बनाना। सुबह उठते ही वह खुद बताए: "कल रात मैंने 15 नए शॉप्स का डेटा निकाला है, क्या मैं उन्हें आउटरीच ईमेल ड्राफ्ट कर दूँ?"
6. JARVIS मुझे खुद CALL भी करे (The "Iron Man" Feel)
अगर कोई important task पूरा हो जाए तो सिर्फ टेक्स्ट notification नहीं चाहिए। मैं चाहता हूँ जार्विस मुझे खुद कॉल करे और बताए।
 * Primary (App-Based Custom Call - VoIP): जार्विस का ऐप मेरे फोन पर एक नॉर्मल कॉल की तरह रिंग करेगा (100% Free)। मैं उठाऊंगा तो जार्विस लाइव बोलेगा: "Krishna, मैंने मीटिंग फिक्स कर दी है, जल्दी आ जाओ।"
 * Secondary / Fallback (Telegram/WhatsApp Voice Note): अगर मैं कॉल नहीं उठा पाता या नेटवर्क इश्यू है, तो जार्विस तुरंत एक ऑडियो मैसेज (Voice Note) ड्रॉप कर देगा।
   (हम पेड टेलीकॉम/सिम कॉलिंग का इस्तेमाल नहीं करेंगे ताकि ₹0-first रूल बना रहे)।

12. Long-running tasks
> “JARVIS, इस business पर complete research करो और report तैयार करो।”
> 
Research → analyse → collect → write → verify → report (चाहे इसमें घंटों लगें)। पूरा होने पर मुझे खुद कॉल करके (VoIP) notify करे।
13. Self-verification
Advanced JARVIS blindly action नहीं लेगा।
Plan → Action → Check → Correct if needed → Verify → Complete.
14. Error recovery (Basic Retry System)
अगर कोई action fail हो: Try → Failure → Retry (Max 1-2 times) → Verify → Notify.
(हम API-heavy infinite self-healing कोडबेस नहीं बनाएंगे ताकि फ्री कोटा खत्म न हो। 1 या 2 बार ट्राई करने के बाद जार्विस सीधे मुझे फेलियर के बारे में बता देगा)।

22. Event-driven JARVIS
JARVIS हमेशा मेरे command का इंतजार नहीं करेगा। Email आया, Meeting आने वाली है, Webhook trigger हुआ → JARVIS खुद action लेगा और मुझे कॉल/वॉइस नोट से बताएगा।
23. FREE / ₹0 requirement (Hard Priority)
Rule: पहले free/open-source/free-tier solution खोजना है।
Free AI APIs, open-source models, free hosting, MCP servers. (लेकिन quotas को ध्यान में रखकर design करना है)।
24. Model routing
Task → JARVIS decides best available FREE model → If quota unavailable → Fallback FREE model। Simple काम fast model को, complex काम stronger model को।
25. MCP (Model Context Protocol)
MCP = JARVIS को अलग-अलग tools से जोड़ने का standardized तरीका। Gmail, Calendar, Files, Browser को MCP से जोड़ना ताकि future में system rebuild न करना पड़े।
26. App & Social Automation (API-Based)
Mobile स्क्रीन पर अनस्टेबल Accessibility-based टैप/स्वाइप करने के बजाय, JARVIS रिलायबल APIs (जैसे Meta Graph API और n8n) का इस्तेमाल करेगा। इससे Instagram, WhatsApp और अन्य प्लेटफॉर्म्स पर बैकग्राउंड में काम 100% एक्यूरेसी के साथ होगा।
27. Wake word
"JARVIS" या "Wake up JARVIS" बोलते ही assistant activate हो और ऐप स्क्रीन पर पॉप-अप होकर खुल जाए। (Lightweight on-device wake-word detection)।
28. Cross-device JARVIS
